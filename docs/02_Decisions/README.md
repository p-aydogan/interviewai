# Architecture Decision Records

This folder will contain durable records of material architecture, product, security, data, dependency, and governance decisions.

## Naming convention

Use:

```text
ADR-###-short-title.md
```

- `###` is a zero-padded sequential number.
- `short-title` is a concise lowercase kebab-case description.

## Required ADR sections

Every ADR must include:

1. Status
2. Date
3. Context
4. Decision
5. Alternatives considered
6. Consequences
7. Risks
8. Rollback approach
9. Related sprints

An ADR records the reasoning and consequences of an approved decision. It does not independently authorize implementation or override sprint scope.

No individual ADR is created as part of the initial governance setup.
